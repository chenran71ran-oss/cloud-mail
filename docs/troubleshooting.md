# 故障排查与 FAQ

[文档中心](README.md) · [部署指南](deployment.md)

先记录失败阶段：构建、部署、初始化、登录、收信还是发信。提供提交 SHA、错误原文和脱敏日志，比单独一张“失败”截图更容易定位。

## 数据库或 KV 绑定失败

**常见原因**：资源已删除并重建，但 TOML 或 Worker 配置仍引用旧 ID。

1. 在 Cloudflare 中确认目标账户、D1 ID 与 KV ID。
2. 同时检查 `wrangler.toml` 中的 `db` 和 `kv` 绑定。
3. 将所有失效引用一起替换为有效资源 ID，再重新部署。
4. 检查部署后的运行时绑定与预期是否一致。

控制台保存单个绑定时也可能验证整个配置。如果另一项仍引用已删除资源，会出现“新的绑不上，旧的也删不掉”。此时应修正完整绑定配置后部署，避免反复删除资源。

同名数据库不代表同一数据库。切换到空的新 D1 后，旧邮件和用户不会自动迁移；先确认是否需要恢复数据。

## 构建成功但网站打不开

检查 `mail-vue` 是否实际完成构建，产物是否进入 `mail-worker/dist`，以及 Worker 的 Assets 是否使用这个目录。

Workers Builds 的根目录应为 `mail-worker`。明确配置 [部署指南](deployment.md) 中的前端构建命令，再看最终部署步骤是否成功。不要只看“依赖安装成功”的日志。

## 初始化返回 JWT secret mismatch

初始化 URL 中的值必须等于 **Worker 运行时**的 `jwt_secret`。检查大小写、空格、Secret 是否保存并应用到当前部署，以及是否误填成 GitHub 的构建变量。

不要把完整初始化 URL 粘贴到 Issue。若密钥已经公开，应更换密钥并检查相关访问记录。

## 初始化显示 success，但不能正常使用

`success` 是初始化接口的返回值；部分迁移会捕获异常并输出警告。若仍有表或字段错误，检查 Worker 日志中的具体 SQL 异常。先备份数据，再按对应版本的升级说明处理，不要立即删库。

管理员应使用 `admin` 配置指定的地址注册。登录密码由注册时设置，与 `jwt_secret` 无关。

## 退信、550 或收不到邮件

| 检查位置 | 需要确认 |
| --- | --- |
| DNS | Email Routing 要求的记录已配置，无冲突 MX |
| Cloudflare 路由 | 指定地址或 Catch-all 已启用，目标 Worker 正确 |
| 邮箱域名 | 收件地址的域名属于 `domain` 配置 |
| 应用账户 | 对应邮箱已创建，用户状态和权限允许收信 |
| 系统设置 | 收信开关、过滤规则和无人收件处理符合预期 |
| Worker 日志 | 是否触发邮件事件，是否有写入或附件错误 |

Catch-all 只解决邮件到 Worker 的路由，不会自动生成所有邮箱账户。先用一个已创建的地址，从外部邮箱发送纯文本测试邮件。

## 收信正常，发信失败

收信与发信是两套配置。检查 Resend 域名验证、发送凭据、发信开关、用户额度与服务返回的错误。使用 Cloudflare 发信绑定时，另行检查账户可用性和限制。

不要仅凭页面提示“已发送”判断外部投递成功；确认服务状态及收件方收件箱、垃圾箱。

## 加了 R2 或 S3 后，历史附件打不开

当前存储选择顺序是完整 S3 配置、R2 绑定、KV。添加绑定或后台凭据可能改变新请求使用的后端，但旧文件不会自动迁移。

先检查附件原本保存在哪里、后台生成的文件域名和实际请求地址。不要为了解决访问问题删除旧存储。备份后再规划文件迁移，参阅 [架构说明](architecture.md)。

## 已配置 Resend，但发信仍走 Cloudflare

存在 `env.email` 绑定时，当前源码会优先使用 Cloudflare 发信；失败不会自动回退到 Resend。核对当前部署的绑定，而不是只检查 Resend Token。

只在确认目标服务和账户能力后调整绑定，重新验证外部实际投递。

## 能用自己的邮箱注册网站吗？

可以尝试使用已经验证能收信的自定义域名邮箱。不同平台可能限制某些域名、要求额外验证或拒绝特定邮箱类型，不能保证所有网站都接受。

用于重要账户时，持续保有域名、维护收信服务并做好备份；邮箱地址需要能长期接收验证与找回邮件。

## 可以托管 QQ、网易等已有邮箱吗？

当前项目主要管理自己域名下的邮箱，没有提供通用的 QQ / 网易 IMAP 账户同步功能，也不能控制 `qq.com` 或 `163.com` 的邮件路由。

如果原服务支持自动转发，可以将新邮件副本转发到自己的域名邮箱。这不等于同步历史邮件、文件夹、已读状态，或获得以 QQ / 网易地址发信的能力。具体转发设置以原服务支持范围为准。

## 更新文档后，为什么 Actions 没运行？

当前 GitHub Actions 的 push 触发路径只有 `mail-worker/**` 和 `mail-vue/**`。只修改 README 或 `docs/` 不会触发该工作流。Cloudflare Workers Builds 的触发规则独立配置，不能用 Actions 状态推断。

## 提交问题时提供什么

使用 [问题模板](https://github.com/chenran71ran-oss/cloud-mail/issues/new/choose)，填写部署方式、提交版本、复现步骤、预期结果与脱敏错误。

不要上传完整邮件正文、收件人列表、Token、密码或包含初始化密钥的地址。疑似安全漏洞按 [安全说明](../SECURITY.md) 处理。
