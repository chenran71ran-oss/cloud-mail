# 上线验收清单

[文档中心](README.md) · [部署指南](deployment.md) · [架构说明](architecture.md)

这是供部署者逐项执行的清单，**不是本仓库实例已经完成所有验证的声明**。首次上线和重要升级后分别保留一份私有验收记录。

## 基础服务

- [ ] 记录当前部署提交 SHA、时间与部署方式。
- [ ] 最新部署成功，网站自定义域名可以访问。
- [ ] 前端页面、登录与 API 正常，无持续请求错误。
- [ ] `db`、`kv` 指向预期账户的有效资源。
- [ ] 首次部署完成初始化，或升级所需迁移已按版本要求核查。
- [ ] 管理员地址与配置一致，能使用自己的登录密码登录。

初始化接口不是健康检查接口。已有实例升级前先备份，避免为了验证网站反复执行迁移。

## 收件

- [ ] Email Routing 的指定地址或 Catch-all 已启用，目标 Worker 正确。
- [ ] 应用内已创建测试邮箱，收信开关与账户权限正确。
- [ ] 从外部服务向该地址发送一封独立测试邮件。
- [ ] 在收件箱核对发件人、收件人、主题、正文和收件时间。
- [ ] 发送带测试附件的邮件，确认附件能够实际下载并打开。
- [ ] 若使用 `+tag` 地址，单独验证 Cloudflare 路由与基础地址匹配。

只使用不含私人信息的测试正文与附件。测试无人收件规则时，应先明确希望拒收还是保存到无人收件区。

## 站外发件（启用时）

- [ ] 确认当前选择的是 Resend 还是 Cloudflare 发信绑定。
- [ ] 所用服务的凭据、域名验证、可用权限与配额满足要求。
- [ ] 从应用向一个外部邮箱发送测试邮件，而不是只做站内互发。
- [ ] 在外部收件人处核对投递、正文与附件，检查垃圾箱。
- [ ] 如启用回复功能，验证实际回复链显示。
- [ ] 检查应用状态与服务状态；不能只凭“发送成功”提示验收。

## 可选集成（启用时）

| 功能 | 验收方式 |
| --- | --- |
| R2 / S3 | 新附件可访问，历史附件访问方式已确认 |
| Workers AI | 测试邮件中的验证码识别符合预期 |
| Telegram / 邮件转发 | 测试消息出现在配置的目标 |
| Webhook | 自己控制的测试端点收到预期数据 |
| Turnstile | 成功与失败验证分别符合预期 |
| 多用户权限 | 非管理员不能访问其他用户的数据或管理功能 |

## 安全与维护

- [ ] 没有将真实密钥、私人邮件或备份上传到公开仓库。
- [ ] 已核对注册、邮箱创建与发件权限，避免无意开放。
- [ ] 已备份 D1 和实际使用的附件存储。
- [ ] 知道如何查看脱敏日志，以及如何恢复代码与数据。
- [ ] 域名续费、服务配额与费用由自己持续维护。

## 验收记录模板

```text
部署提交：
验收时间与时区：
部署方式：
验证范围：
通过项：
未启用项：
未通过项与错误摘要（脱敏）：
备份位置（私有记录，不公开）：
下一步：
```

出现问题时，按 [故障排查](troubleshooting.md) 记录失败阶段；公开求助只提交脱敏摘要。
